本项目采用前后端分离架构，各自拥有独立的构建系统，无统一的 CI/CD 或容器化配置。

**前端（frontend）**
- 基于 Vite + Vue3 + TypeScript 的单页应用，通过 `pnpm` 管理依赖。
- 构建脚本定义在 `package.json`：`dev` 启动开发服务器，`build` 先执行 `vue-tsc -b` 类型检查再 `vite build` 产出静态资源到 `dist/`，`preview` 本地预览产物。
- `vite.config.ts` 配置了 `@` 路径别名、自动导入（`unplugin-auto-import`）、开发代理 `/proxy -> http://127.0.0.1:39120`，以及忽略对 `white.json` 的热重载。
- CSS 管线：PostCSS + TailwindCSS + Autoprefixer，样式主题通过 CSS 变量扩展品牌色、阴影、动画等。
- 图片优化：提供 Node 脚本 `scripts/compress-images.mjs`，使用 `sharp` 递归压缩 `public/images` 和 `vibe_images` 下的图片至 ≤800KB，按质量阶梯与最长边尺寸双维度搜索最优解。
- 资源打包：`index.html` 作为入口，`public/` 下静态资源直接拷贝，`vite build` 输出带 hash 的静态文件。

**后端（server）**
- 基于 Webman（Workerman）PHP 框架，以插件式架构组织业务，所有业务逻辑位于 `server/plugin/` 下（如 `xbAiAsset`、`xbUser`、`xbUpload*` 等），每个插件自包含 `api/app/config/data/enum/public/setting/skills` 等目录。
- 依赖通过 `composer.json` 声明，核心依赖包括 `workerman/webman-framework ^2.1`、`webman/*` 系列扩展、`symfony/workflow`、`guzzlehttp/guzzle`、各云存储 SDK（腾讯云 COS、阿里云 OSS、七牛）及短信/邮件服务 SDK。
- 启动入口为 `webman` CLI 命令（`php webman start/restart/stop/status/reload/connections`），内部加载 `.env`、时区、错误报告级别，并扫描主应用与插件的 `command` 目录注册自定义命令。
- 进程模型：`config/process.php` 定义 HTTP、Monitor 等常驻进程；`runtime/windows/` 下提供 Windows 平台的多进程启动脚本（含队列消费者、定时任务等）。
- 数据库与缓存：ThinkORM + ThinkCache 集成，Redis 用于会话、缓存与队列（`webman/redis-queue`）。
- 部署：`composer.json` 引入 `deployer/deployer ~7.5`，但仓库未包含 `deploy.php`（被 `.gitignore` 排除），说明部署流程由外部工具或手动完成。
- Nginx 反向代理：`nginx.conf` 将非静态文件请求转发到 `http://127.0.0.1:39120`（Webman 默认端口）。

**约定与约束**
- 前后端通过 Vite 开发代理联调，生产环境由 Nginx 统一反代到 Webman 进程。
- 插件是后端功能扩展的最小单元，需遵循标准目录结构并通过 `plugins.json` 注册。
- 无 Dockerfile、Makefile、GitHub Actions 等自动化构建/发布配置，构建与部署目前依赖开发者本地环境与手动操作。
