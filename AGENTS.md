# AGENTS.md

This file provides guidance to Qoder (qoder.com) when working with code in this repository.

## Project Overview

This is **积木云 (jymc.dev)** — an AI-powered comic/short drama production platform. It consists of:

- **Frontend**: Vue 3 SPA (Vite + TypeScript + Tailwind CSS + Pinia)
- **Backend**: PHP 8.1+ server based on **Webman** framework (workerman-based, plugin architecture)

The app lets users create comic episodes with AI-generated assets (images, videos, audio) using various AI model providers.

## Development Commands

### Frontend (`frontend/`)

```bash
# Install dependencies
pnpm install

# Dev server (hot-reload, proxies /proxy → http://127.0.0.1:39120)
pnpm dev

# Production build (type-check + vite build)
pnpm build

# Type-check only
npx vue-tsc -b
```

### Backend (`server/`)

```bash
# Start server (Linux/Mac)
php start.php start

# Start server (Windows)
php start.php start -d
# or use: windows.bat

# Stop server
php start.php stop

# Restart server
php start.php restart
```

The backend runs on **port 39120** by default. The frontend dev server proxies `/proxy/*` to this backend.

## Architecture

### Frontend Architecture

**Custom UI Library (`xbUi/`)**: The project uses a self-built component library prefixed with `Xb` (e.g., `XbButton`, `XbModal`, `XbSelect`). These are globally registered as a Vue plugin. Always use these components instead of raw HTML elements or third-party UI libs.

**Request Layer (`utils/request/`)**: All HTTP calls go through a custom `RequestClient` class wrapping Axios. The default singleton `request` is exported from `utils/request/index.ts`. API modules live in `src/api/*.ts`. The base URL is `/proxy` (dev) which gets rewritten by Vite proxy.

**White-list routing (`utils/request/white.json`)**: API paths in this file bypass authentication. This file is auto-generated by the backend `WhitelistScanner` process — do NOT edit manually. Vite is configured to ignore changes to this file to prevent hot-reload loops.

**Auto-imports**: Vue, Vue Router, and Pinia APIs are auto-imported via `unplugin-auto-import`. You do NOT need to import `ref`, `computed`, `onMounted`, `useRouter`, `defineStore`, etc.

**Path alias**: `@` maps to `frontend/src/`.

**Stores (`stores/`)**: Pinia stores for `user`, `siteConfig`, `projects`, `assets`, `marketplace`.

**Key views**:
- `HomePage` — landing page
- `MyWorks` — user's comic works
- `EpisodesPage` — episode creation pipeline (create → entities → storyboard → generate → preview)
- `AssetsPage` / `AssetsGeneratePage` — asset management and AI generation
- `MarketplacePage` — asset marketplace
- `CommunityPage`, `HelpCenterPage`

### Backend Architecture

**Webman framework**: High-performance PHP framework based on workerman (persistent process model, NOT traditional request-response like Laravel). All routes are handled by long-running processes.

**Plugin system (`plugin/`)**: The backend is heavily plugin-based. Each plugin has its own:
- `config/` — routes, middleware, menu, process, dict bindings
- `app/` — controllers (admin + api), models, services
- `api/` — public-facing API classes
- `enum/` — domain enums
- `config/menu.php` — admin panel menu definition
- `config/xbcode.php` — plugin metadata and settings

**Key plugins**:
- `xbAiModelAgent` — **core AI plugin**: model management, media generation (image/video/audio), chat, task queue (TaskServer process), pricing/billing
- `xbMovieApp` — main application plugin: site config, episode/asset management, whitelist scanner
- `xbUser` — user authentication and management
- `xbUpload` / `xbUploadCos` / `xbUploadOss` / `xbUploadQiniu` — file upload with multi-cloud support
- `xbCode` — core framework plugin
- `xbCdKey`, `xCoupon`, `xbSms*`, `xbEmail` — auxiliary plugins

**Admin panel**: The backend auto-generates admin CRUD pages via **amis** (JSON-based low-code framework). Admin controllers return amis JSON schemas, not HTML. The admin panel is accessed at `/backend`.

**Task processing (`process/TaskServer.php`)**: Background process for AI media generation tasks. Runs as a workerman process, polls task queue, dispatches to AI providers, handles billing (pre-deduct + settle).

**Database**: MySQL via ThinkORM (think-orm). Table prefix: `xb_`. Config in `.env`.

**Cache/Queue**: Redis for queues (`webman/redis-queue`), file or Redis for cache.

### Frontend-Backend API Convention

API paths follow the pattern: `/app/{pluginName}/api/{ControllerName}/{method}` or plugin-defined routes like `/api/chat/completions`, `/api/media/generate`.

All API responses follow a standard structure:
```json
{ "status": 0, "data": {}, "msg": "success" }
```
The `RequestClient` automatically unwraps `.data.data`, so frontend API functions receive the inner `data` directly.

### Enums Pattern

Backend uses PHP enums extensively in `plugin/xbAiModelAgent/enum/` for model modalities, image/video sizes, task statuses, pricing units, etc. Frontend has corresponding TypeScript enums/types in `src/api/modelEnum.ts`.

## Coding Conventions

- **Vue components**: Use `<script setup lang="ts">` with Composition API
- **Styling**: Tailwind CSS utility classes; custom CSS variables for theming
- **Forms**: Backend admin forms use amis JSON schema via `addRowStatic()` pattern
- **Amount fields**: Use `decimal(10,4)` in DB; always round with proper precision in calculations
- **State enums**: Reuse `StateEnum` pattern (values `10`=disabled, `20`=enabled) across plugins
- **Grid layout**: Backend admin forms use amis grid with `md` column config for responsive layout
